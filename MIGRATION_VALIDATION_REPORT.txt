ISSUE 1: contentArchive Column Reference Bug (Errors 13-25)
----------
Migration 0007 attempts to UPDATE contentArchive with references to columns 
that don't exist:

    UPDATE `contentArchive`
    SET `vocabulary` = JSON_ARRAY(JSON_OBJECT(
        'word', `content`, 
        'definition', `definition`, 
        'usage', `notes`
    ))
    WHERE `contentType` = 'vocabulary';

PROBLEM:
  - contentArchive was created in 0001 with: 
    id, userId, contentId, contentType, archivedDate, proficiencyLevel, notes, createdAt

  - Migration 0007 ADDS: generatedDate, vocabulary, grammar, readingMaterial, exercises

  - But the UPDATE statements reference `content` and `definition` columns
    that are NOT being added to contentArchive

IMPACT:
  - 4 UPDATE statements (all with WHERE contentType IN (vocabulary, phrase, sentence, passage))
  - Each tries to build JSON by referencing non-existent `content` and `definition`
  - Database will raise "Unknown column" error at runtime
  - Migration 0007 will FAIL

FIX REQUIRED:
  - The UPDATE statements should reference existing columns from contentArchive
  - Currently only `notes` is available from the original schema
  - Consider whether the data migration logic is correct


ISSUE 2: Statement Execution Order Problem in generatedContent (Errors 1-12)
----------
The migration references JSON columns before they are created:

Migration flow:
  1. ALTER TABLE `generatedContent`
     ADD COLUMN `vocabulary` json NOT NULL DEFAULT '[]'
     ADD COLUMN IF EXISTS... (multiple JSON columns)
  
  2. UPDATE `generatedContent`
     SET `vocabulary` = JSON_ARRAY(...)  [REFERENCES vocabulary BEFORE it's added]
     WHERE `contentType` = 'vocabulary';

NOTE: Upon inspection, this appears to be caused by a statement parsing issue.
The ADD COLUMN statements DO exist and precede the UPDATE statements in the 
migration file. However, the schema validator detected missing columns at 
update time. Check the actual statement ordering in 0007_align_schema.sql.
